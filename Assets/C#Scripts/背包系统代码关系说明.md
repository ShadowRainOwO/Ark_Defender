# 背包、仓库、容器与商店代码关系

## 1. 总体分层

```text
场景交互层 Interaction
    ↓ 发起“打开谁”的请求
UI 层 UI/Inventory ──────────────┐
    ↓ 绑定并显示数据              │ 调用业务操作
数据层 Data                      ↓
    ↑ 被读取和修改          逻辑层 Logic
    └─────────────────────────────┘
```

- `Data`：保存物品配置和运行时内容，不负责打开界面。
- `UI`：显示数据并上报玩家操作，不直接修改容器内容。
- `Logic`：执行物品转移、购买、出售、装备等业务规则。
- `Interaction`：检测玩家正在面对谁，并把具体对象交给 UI 或 Logic。

依赖方向应该保持为：上层可以使用下层数据，但数据类不要反过来引用 UI。

## 2. 物品与普通容器

```text
ItemData（静态配置资源）
    ↓ 被引用
ItemStack（一个格子的物品与数量）
    ↓ 被保存
IItemContainer（统一容器接口）
    ↑
ItemContainerData（通用实现）
    ├── PlayerInventory（玩家背包）
    ├── StorageData（玩家仓库）
    └── ContainerData（场景容器）
```

### ItemData

ScriptableObject 静态配置，保存 ID、类型、最大堆叠、重量、基础价值、说明和图标。同一种物品只需创建一份资源。

### ItemStack

运行时格子数据，保存“引用哪个 ItemData”和“当前数量”。物品数量不能写回 ItemData，否则所有引用同一资源的物品都会被影响。

### IItemContainer

背包、仓库和场景容器的统一操作约定。UI 和 `ItemTransferManager` 面向该接口工作，不需要判断具体容器类型。

### ItemContainerData

实现格子维护、堆叠、添加、移除、容量调整和 `Changed` 事件。`StorageData` 与 `ContainerData` 当前主要用于区分业务身份；`PlayerInventory` 在此基础上增加人物属性容量同步。

## 3. 玩家背包容量来源

```text
PlayerBaseData.DefaultInventorySlots（默认格子）
                         +
PlayerStats.ExtraInventorySlots（装备/天赋/升级额外格子）
                         ↓
PlayerStats.TotalInventorySlots
                         ↓
PlayerInventory.TrySetSlotCount
                         ↓
InventoryPanel 读取 PlayerInventory.SlotCount
```

- 默认容量属于角色静态配置，保存在 `PlayerBaseData`。
- 额外容量属于运行时人物属性，保存在 `PlayerStats`。
- 实际容器容量由 `PlayerInventory` 统一同步。
- UI 不直接相加两份人物属性，只读取 `PlayerInventory.SlotCount`，避免显示容量和实际可存放容量不同。

运行时增加或减少容量时，应调用：

```csharp
playerInventory.TrySetExtraInventorySlots(newExtraSlots);
// 或者在现有额外容量上增减
playerInventory.TryAddExtraInventorySlots(delta);
```

缩容时，如果将被移除的尾部格子中仍有物品，操作会返回 `false`，人物属性和实际容量都不会改变。

## 4. 普通容器 UI

```text
SlotPanelBase（Title + SlotArea + 自动补充空格子）
    ├── ItemContainerPanel（普通容器数据绑定）
    │   ├── InventoryPanel（背包视图）
    │   ├── StoragePanel（仓库视图）
    │   └── ContainerPanel（场景容器视图）
    └── ShopPanel（商店视图）

SlotPanelBase
    └── 检查并创建多个 ItemSlot Prefab 实例
```

### SlotPanelBase

负责四种页面共同拥有的最基础结构：

- 查找并设置 `Title`。
- 查找 `SlotArea`。
- 统计 `SlotArea` 下已经存在的 `ItemSlot`。
- 如果少于目标数量，只实例化缺少的部分。
- 如果多于目标数量，隐藏多余格子而不销毁。

例如仓库需要 20 格，当前 `SlotArea` 已有 4 个 ItemSlot，则只会再生成 16 个。

### ItemSlot

只负责显示一个格子的图标、数量和选中状态，并发出单击/双击事件。它不应该直接调用 `PlayerInventory.Add` 或 `StorageData.RemoveAt`。

### ItemContainerPanel

在 SlotPanelBase 之上绑定任意 `IItemContainer`，监听其 `Changed` 事件，并统一刷新所有 ItemSlot。没有绑定数据时使用页面配置的基础格子数量；绑定后使用真实容器的 `SlotCount`。

### InventoryPanel / StoragePanel / ContainerPanel

当前行为相同，但具体类型让 `InventoryUIManager` 能准确找到相应面板。以后各自专属功能应放在对应子类，例如：

- `InventoryPanel`：负重、整理。
- `StoragePanel`：搜索、分类、容量升级。
- `ContainerPanel`：全部拾取、容器名称。

## 5. 商店为什么单独处理

```text
ShopData
    └── ShopEntry（商品、库存、买价、卖价）

ShopPanel  ←监听─ ShopData.Changed
ShopManager ─修改→ ShopData + 玩家金币 + 目标容器
```

商店不实现 `IItemContainer`，因为“把商品放进背包”不是普通转移，还必须检查库存、金币、价格和背包容量。

- `ShopData`：只保存商品目录和库存。
- `ShopPanel`：显示商店数据。
- `ShopManager`：唯一允许执行购买和出售的业务入口。

不要使用 `ItemTransferManager` 把商店商品直接移入背包，否则会绕过金币检查。

## 6. InventoryUIManager 的作用

`InventoryUIManager` 是界面编排器，不是物品管理器。它负责：

- 绑定本次要显示的背包、仓库、容器或商店数据。
- 把面板移动到 `LeftSlot` 或 `RightSlot`。
- 控制根界面、关闭按钮和商店来源切换按钮。

布局状态：

| 模式 | 左侧 | 右侧 |
|---|---|---|
| InventoryOnly | 空 | 背包 |
| Storage | 背包 | 仓库 |
| ShopInventory | 背包 | 商店 |
| ShopStorage | 仓库 | 商店 |
| Container | 场景容器 | 背包 |

## 7. Interaction 调用关系

```text
InteractionManager
    └── 找到最近的 IInteractable
            ├── ContainerInteract → ContainerManager → InventoryUIManager
            ├── StorageInteract ─────────────────────→ InventoryUIManager
            ├── NPCInteract（有 ShopData）────────────→ InventoryUIManager
            └── DoorInteract → 切换门状态
```

### 打开场景容器

```text
玩家按交互键
→ InteractionManager 调用 ContainerInteract.Interact
→ ContainerManager 记录 ActiveContainer
→ InventoryUIManager.OpenContainer(containerData)
→ ContainerPanel 绑定该 ContainerData
→ InventoryPanel 绑定 PlayerInventory
```

### 打开仓库

```text
StorageInteract
→ InventoryUIManager.OpenStorage(storageData)
→ 左侧 InventoryPanel，右侧 StoragePanel
```

### 打开商店

```text
NPCInteract
→ InventoryUIManager.OpenShop(shopData)
→ 左侧 InventoryPanel，右侧 ShopPanel
→ 点击切换按钮后变为左侧 StoragePanel，右侧 ShopPanel
```

## 8. 物品操作调用关系

### 普通转移

```text
ItemSlot 上报点击/双击
→ 上层决定来源与目标
→ ItemTransferManager.Transfer
→ 来源 RemoveAt + 目标 Add
→ 两个容器触发 Changed
→ 对应 ItemContainerPanel 自动 Refresh
```

### 购买

```text
商店商品按钮
→ ShopManager.Buy
→ 检查商品、库存、金币、背包容量
→ 修改 ShopData、目标容器和玩家金币
→ ShopPanel 与 ItemContainerPanel 刷新
```

### 装备

`EquipmentManager.TryEquip` 当前只替换武器或护甲引用，并返回旧装备；从背包扣除新装备、把旧装备放回背包的完整流程尚未连接。

## 9. 当前仍未连接的部分

以下不是代码关系错误，而是下一阶段需要补齐的功能：

1. `ItemSlot` 的双击事件已经上报，但还没有一个 UI 操作协调器根据当前左右面板自动调用 `ItemTransferManager`。
2. `ShopPanel` 已能生成基础空格子，但还没有把 `ShopEntry` 的图标、价格、库存和购买按钮绑定到格子上。
3. `ShopManager.Sell` 暂时按基础价值一半出售，售出物不会进入商店回购列表。
4. `ShopManager` 暂时自己保存金币，正式存档前适合拆成独立 `WalletData`。
5. `EquipmentManager` 尚未和背包物品数量联动。
6. `InteractionManager` 的交互提示目前仍是 Debug 日志。

## 10. Inspector 基础配置

- 玩家：挂载 `PlayerStats` 和 `PlayerInventory`，并为 `PlayerStats` 指定 `PlayerBaseData`。
- 仓库对象：挂载 `StorageData`、`StorageInteract`。
- 场景容器：挂载 `ContainerData`、`ContainerInteract`。
- 商店 NPC：挂载或引用 `ShopData`，并赋给 `NPCInteract`。
- UI 根对象：挂载 `InventoryUIManager` 并配置左右挂点、四个面板和按钮。
- 背包/仓库/容器面板：分别挂载具体 Panel，并配置 `ItemSlot` 预制体与格子根节点。
- 系统管理对象：根据需要挂载 `ItemTransferManager`、`ShopManager`、`ContainerManager` 和 `EquipmentManager`。
